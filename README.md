# Імітаційна модель передачі цифрового мовлення (курсова робота, варіант B8)

Модель передачі пакетів цифрового мовлення, побудована як мережа масового обслуговування. Алгоритм просування модельного часу реалізовано самостійно, без SimPy та інших бібліотек імітації. Структура класів відповідає лекції 4: `Element` → `Create`, `Process`, `Sink`; `Model`; `FunRand`.

## Опис моделі

- **Надходження.** Пакети надходять із інтервалом, рівномірно розподіленим на [3; 9] мс (середнє 6 мс).
- **Канали.** Кожен пакет послідовно обслуговують два канали, K1 та K2, кожен з FIFO-чергою. Тривалість обслуговування становить 5 мс, а з підключеним додатковим ресурсом (R = 1) — 4 мс. Тривалість визначається в момент початку обслуговування.
- **Знищення.** Пакет знищується, якщо його час перебування в мережі T > 10 мс (допуск 1e-9).
- **Керування ресурсом.** Контролер стежить за ковзним вікном з N = 100 останніх пакетів. Рішення ухвалюються лише після заповнення вікна:
  - ресурс підключається, коли частка знищених у вікні ≥ θ = 0.30;
  - ресурс вимикається, коли частка знищених < θ_off (за замовчуванням θ_off = θ).
- **Одночасні події.** Пріоритет: K2 → K1 → надходження.
- **Час.** Усі значення часу вказано в мілісекундах.
- **Статистика.** Модель збирає частку та частоту знищених пакетів, частоту підключень ресурсу, частку часу з R = 1, середні довжини черг, завантаження та час очікування (зважені за часом). Після періоду розгону T_warm статистика скидається.
- **Режими керування** (`control_mode`): `adaptive` (за порогом), `never` (ресурс ніколи не підключається), `always` (ресурс підключено завжди).

### Структура проєкту

```
simulation/        ядро моделі
  config.py          параметри моделі (ModelConfig)
  fun_rand.py        генератори випадкових величин (FunRand)
  packet.py          пакет і записи про проходження вузлів
  element.py         базовий клас Element
  create.py          генератор пакетів (Create)
  process.py         канал обслуговування з чергою (Process)
  sink.py            вихід мережі, перевірка порогу знищення (Sink)
  resource_state.py  стан додаткового ресурсу
  controller.py      контролер ресурсу з ковзним вікном
  model.py           календар подій і просування часу (Model)
  analytics.py       аналітичні формули (M/M/1, мережа Джексона)
experiments/       сценарії експериментів
  common.py          паралельні прогони, довірчі інтервали, запис CSV
  plotting.py        спільний стиль графіків
results/           усі результати (CSV, PNG, TXT, JSON)
```

## Встановлення

Потрібен Python 3.13. Перевірено з numpy 2.2.3, scipy 1.18.1 та matplotlib 3.10.7.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS
pip install -r requirements.txt
```

## Запуск експериментів

Усі скрипти запускаються з кореня проєкту командою `python -m experiments.<назва>`. На Windows для коректного виводу кирилиці в консоль варто встановити `PYTHONIOENCODING=utf-8`.

Скрипти потрібно виконувати в наведеному порядку. `transient` і `replications` записують у `results/run_params.json` параметри T_warm, T_mod і кількість прогонів, а всі наступні експерименти їх читають.

| № | Команда | Що робить | Результати |
|---|---------|-----------|------------|
| 1 | `python -m experiments.verification` | Верифікація: 18 сценаріїв із передбачуваним результатом, протокол подій | `verification.csv`, `event_protocol.txt`, `event_protocol_switch.txt` |
| 2 | `python -m experiments.validation` | Перевірка за аналітикою (експоненційні розподіли, M/M/1 і мережа Джексона) | `validation.csv` |
| 3 | `python -m experiments.transient` | Перехідний період: визначення T_warm (метод Велча) і T_mod | `transient.csv`, `transient_*.png`, `run_params.json` |
| 4 | `python -m experiments.replications` | Необхідна кількість прогонів за нерівністю Чебишова (β = 0.95, ε = 1%) | `replications.csv`, `replications_required.png`, `run_params.json` |
| 5 | `python -m experiments.run_base` | Базовий сценарій B8, порівняння режимів `adaptive`/`never`/`always`, дисперсійний аналіз | `base_summary.csv`, `base_modes.csv/png`, `base_anova.csv`, `base_sojourn_histogram.png` |
| 6 | `python -m experiments.factors` | Однофакторні експерименти: інтервал надходження, розмір вікна N, поріг θ | `factor_*.csv`, `factor_*.png` |
| 7 | `python -m experiments.proposals` | Пропозиції щодо покращення: гістерезис, зміна θ і N, парний t-тест | `proposal_*.csv`, `proposal_*.png` |

Окремий фактор можна запустити так: `python -m experiments.factors --factor interval` (можливі значення: `interval`, `window`, `threshold`, `all`).

Прогони виконуються паралельно на всіх ядрах процесора. Повний цикл усіх скриптів займає кілька десятків хвилин. Результати детерміновані: для фіксованих seed повторний запуск дає ті самі файли.

## Результати

Усі результати зберігаються лише в каталозі `results/`:

- **`*.csv`** — таблиці з середніми та напівширинами 95% довірчих інтервалів. Кодування UTF-8 з BOM, тому файли коректно відкриваються в Excel.
- **`*.png`** — графіки. Осі підписано з одиницями, а в підписі під графіком вказано час моделювання, T_warm і кількість прогонів.
- **`run_params.json`** — обрані T_warm, T_mod, кількість прогонів і проміжні дані для їх обґрунтування.
- **`event_protocol*.txt`** — протоколи подій для верифікації.

Регресію для інтервалу надходження (`factor_interval_regression.csv/png`) побудовано на ділянці 5–8 мс. Плато для інтервалів ≥ 8 мс описано окремо у `factor_interval_plateau.csv`. Тут мінімальний інтервал між пакетами не менший за час обслуговування (5 мс), тому черги не утворюються, час перебування дорівнює рівно 10 мс і знищень немає.
